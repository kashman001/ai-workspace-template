Maintaining this backlog

Treat this file as a lightweight issue tracker for the template itself. Settled cards (Resolved / Decided / Won't fix) live in template-workspace-backlog-archive.html — this file holds Open cards only, so agents can read it cheaply; the scorecard counts span both files. Agents: edit both files with targeted reads (grep the ID / section), never whole-file loads. The rules:

  1. IDs are stable and severity-scoped. High, Medium, Low, Decision + a number (e.g. M6). Never renumber or reuse an ID — once assigned it's permanent, even after the item is resolved.
  2. Every finding carries a status badge: Open · Resolved · Decided · Won't fix.
  3. When you fix an item: flip its badge to Resolved, add a Fixed: line describing the change (and the commit/PR if handy), and add class="resolved" to its <div class="find …">; then move the whole card to the matching severity section of template-workspace-backlog-archive.html.
  4. When you find a new issue: append a new finding card under the right severity heading with the next free ID, status Open, and the Evidence / Impact / Fix lines.
  5. Update the scorecard counts and the "Last updated" date in the header on every change.
  6. Deliveries from other sessions/clones follow the same rules. A template change pushed from a downstream session must carry its backlog update in the same push; the session that pulls a change lacking one adds the missing row/card as part of incorporating it (see L14).
  7. Commit convention: reference the ID, e.g. git commit -m "Fix M6: …", so the git log and this file stay in sync.
  8. Re-review trigger: after any structural change to the template (new config file, new doc, new agent runtime), do a fresh evidence pass and append what it surfaces.

Tip: the matching skill for turning these into real tracked issues is to-issues (see docs/recommended-tooling.md) if you'd rather move them to GitHub Issues.

M16 EnterWorktree mid-session stales the registry artifact path — wrongful stale-primary sweeps MediumOpenscripts/context-budget.sh · ADR-0006

Evidence — change-log finding 2026-08-06 (session 24), previously un-carded: entering a worktree relocates the claude transcript to a worktree-scoped project directory, so the artifact path pinned at register goes stale; two live primary-takeover incidents. Reproduced 2026-08-08 (usage-scenarios session 2): record after EnterWorktree shows the artifact path switching to …-claude-worktrees-usage-scenarios-s2/… while the lock was registered under the launch-dir path.

Impact — the pinned artifact stops updating → holder looks dead → stale-primary sweep or takeover fires against a live session.

Fix — re-pin the artifact at record time when the session-id's transcript has moved (the session id is stable across the move), or a worktree-entry hook that re-registers; add a regression test with a relocated artifact fixture.

Low

L32 In-band WARN push swallowed when a busy child wins the throttle race LowOpenscripts/hooks/ (claude runtime)

Evidence — change-log finding 2026-08-06 (session 24, ticket 06 empirical run), previously un-carded: the hook throttle key is shared, so a subagent's hook firing can consume the escalation-once slot under the parent session id and the parent never sees the WARN push.

Impact — a session can cross WARN unnotified and drift toward STOP/auto-compaction territory; defeats the consent-point design.

Fix — key the throttle/escalation state per (session-id, main-vs-sidechain) instead of per session id alone; cover with a vendor-hook test that fires a sidechain event first.

L33 Launcher staleness race: successor trusts a stale next-session.md when the checkout lags origin LowOpenskills/session-rollover · scripts/launch-next-session.sh

Evidence — change-log finding 2026-08-06, previously un-carded: a successor session read a stale launcher because the local checkout lagged origin/main; mitigation is prose-only. Same shape recurred 2026-08-08 session 2: a fresh worktree branched from origin/main, which lagged local main by the session-1 commit — caught only because the work files were visibly missing.

Impact — successor resumes from an outdated plan; wasted work or conflicting edits.

Fix — cheap freshness guard at bootstrap: compare the launcher's last-commit sha against origin (and against local main when branching a worktree); warn and stop if behind.
