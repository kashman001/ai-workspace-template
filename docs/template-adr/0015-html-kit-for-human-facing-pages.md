# TADR-0015: Write human-facing HTML pages as content on a shared kit (`docs/kit/`)

- Status: accepted
- Date: 2026-10-18
- Deciders: Kashif + Claude Code sessions 1–10 of `html-kit`

## Context

The template's human-facing pages (setup guide, slide decks, one-off reports) were
written by agents as self-contained HTML: every page carried its own `<style>`,
scripts and hand-coloured SVG. Measured on real pages, 30–95% of each file was
styling and drawing code, so every page paid that token cost again, looked a little
different from the last one, and often had no working dark mode.

Two hard requirements came from the user: diagrams for humans must stay good (Mermaid
alone lost spatial layouts and drew dense graphs tiny), and the approach must work
for every agent runtime the template supports, not only Claude Code.

## Decision

Human-facing pages are content-only HTML on a shared kit in `docs/kit/`: `kit.css`
and `kit.js` do all design, behaviour and light/dark theming; `AUTHORING.md` (and
`DIAGRAMS.md` for figures) is the rule an author loads. HTML stays the source of truth
for these pages. Concretely:

- No `<style>`, no `style=`, no script besides the kit line.
- Diagrams are Mermaid or a hand-drawn `<svg class="diagram">` — **SVG allowed but
  themed**: no colour or font attributes and no `<defs>`; kit classes colour it.
- **Render-check rule**: a page with figures is not done until someone with Chrome
  has run `docs/kit/render-check.sh` (1280 and 390 wide, light and dark) and viewed
  every shot. An author that can't run it says so and hands back. Greps and
  `check-links.sh` are necessary but say nothing about how a figure looks.
- Rollout is small: `docs/setup-guide.html` is converted now; every new human-facing
  page uses the kit; other pages convert at their next edit; the two backlog pages
  stay as they are.
- The kit is plain CSS/JS plus Markdown rules and two shell scripts, so any runtime
  can use it — no runtime-specific skill.

## Alternatives considered

- **Keep self-contained pages** — rejected: the measured 35–50% token saving per page
  and consistent light/dark rendering are lost, for a small kit to maintain.
- **Mermaid-only diagrams** — rejected: spatial layouts and dense graphs regressed
  below what the user accepts for human-facing pages.
- **Convert every existing page now** — rejected: the backlog pages are large, churn
  constantly and have their own upkeep rules; conversion is the only cost that grows
  per page, so it waits for each page's next edit.
- **Trust grep checks for figures** — rejected: in every cross-runtime round the greps
  passed while figures were clipped, overlapped or tiny; only viewing shots caught it.

## Consequences

- Pages are smaller and look alike; dark mode comes free. Changing the look means
  editing `kit.css` once — and re-checking every page with figures.
- Cross-runtime evidence (rules alone, then after seeing shots): Codex 0/5 → 4/5
  figures right, Gemini (Antigravity) 2/5 → 5/5, Copilot CLI (on the fixed rules)
  4/5 → 5/5. All produced rule-clean pages; figure quality depends on the render
  check, which sandboxed CLIs could not run (Chrome aborts in their sandboxes).
  So a page with figures still needs a runtime with Chrome — here, Claude Code — to
  review it. That is the cost we're least happy about.
- `render-check.sh` needs Chrome and network (Mermaid from a CDN); shots go to the
  temp dir and are never committed.
- `docs/workspace-structure.html` is still generated by `scripts/build-guide-html.sh`
  with its own embedded stylesheet; moving that generator onto the kit is open work.
