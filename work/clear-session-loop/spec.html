1. Design overview

A Claude Code session can already roll over in place: launch-next-session.sh --clear writes the bootstrap prompt plus this process's pid into launch.pending (scripts/launch-next-session.sh:282-285,430-435), the human presses /clear, and the SessionStart hook's register matches the pid, binds the new session id and prints the prompt into the cleared context (scripts/context-budget.sh:788-795,847-850,865-877).

The research found no case for building more on /clear (no sanctioned trigger but a keypress; the gains are startup time only; portability is weakest there). It did find three cheap fixes that protect the setup we already have:

  1. Owner check in the turn-end hook before it kills anything (§2).
  2. Optional PreCompact hook that blocks auto-compaction while a work item is bound, off by default (§3).
  3. Test the "types nothing" claim once and make the docs match (§4).

Nothing changes on any runtime other than Claude Code, and nothing changes in session-loop.sh or the record schema.

2. Turn-end owner check

  • S4 — the turn-end hook checks the current owner before any SIGTERM. Today budget_hook_should_exit fires on .staged != null and .staged.by == $sid (scripts/hooks/context-budget-hook-lib.sh:124-134) and budget_hook_exit then runs kill -TERM $PPID (:141). Requirement: the predicate becomes .staged != null and .staged.by == $sid and .session.session_id == $sid. Why: after a /clear the live process has a new session id, while a surviving background child (changelog 2.1.72, research §2.1) still fires hooks with the old one. scripts/hooks/context-budget-hook.sh:111-113 routes those to a -sidechain key for measurement, but the end branch at :81-91 runs before that routing. The research did not reproduce a kill from this path; the check is cheap insurance. Test: record with staged.by == sid and session.session_id != sid → no signal; both equal → signal (today's behaviour).

3. Optional PreCompact auto-block

  • S13 — opt-in auto-compaction block. A new PreCompact hook entry in .claude/settings.json with matcher auto and shim scripts/hooks/context-budget-precompact-hook.sh. It exits 2 (blocks, per the hooks page exit-code table — research Verification) only when CONTEXT_BLOCK_AUTOCOMPACT=1 is set in context-budget.env (or the work item's copy) and this session owns a work item (resolve_own_project succeeds). manual is never matched. Off by default: on a session that ignored STOP, a blocked compaction is a hard wall at the model's window, not a rollover. Fail-open on every error (no jq, no record, no env). Test: fixture payloads trigger: auto|manual × env on/off × owner/non-owner → exit code only.

The stage-2 probe typed a message after /clear (work/template-improvement-review/evaluation/stage2-probes.md:51), so it does not settle it. Unverified today.
