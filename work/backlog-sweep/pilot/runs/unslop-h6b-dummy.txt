## Proposed Approach: Moving Session Storage To Postgres

Our session store is a single Redis instance, and it has become a bottleneck.

**Current State:** Sessions live on one Redis node with no replica. A restart in August logged out roughly 18,000 users.

**Proposal:** Store sessions in a new `sessions` table in the existing Postgres cluster, which already has three replicas. A nightly job would remove expired rows to keep the table small.

**Trade-offs:** Session reads are expected to rise from about 1ms to about 4ms at p99. That should be acceptable given our 200ms page budget.

**Rollout:** Roll out in phases: dual-write for two weeks, then switch reads, then remove Redis.

We expect this change to improve reliability.
