Workspace docs · condensed

Context budget

Models get worse past about 150K tokens of context, whatever the advertised window. The workspace measures each session's real usage from disk, warns before that line, and hands work to a fresh session on purpose instead of letting automatic compaction decide.

Why measure from disk

Token usage lives in the API response envelope, which the model never sees. Agents guess their own usage badly, and optimistically. So the number always comes from the runtime's session file on disk; the agent only asks for a measurement at checkpoints.

The agent is never the source of the number. It invokes the measurer and acts on the exit code.

Thresholds

Absolute token counts, not a percentage of the window: a 936K window does not move the point where quality drops. One pair applies to every session and role.

LevelTokensExit codeResponse
OKbelow 120,0000Keep working
WARN120,0001Finish the unit, then ask the user whether to roll over
STOP150,0002Finish only the current atomic step, then roll over — no ask
Error—3Measurement failed; fix the setup

Keep STOP below the runtime's own auto-compact trigger (150K is under Claude Code's ~200K), or compaction fires before the deliberate rollover gets a chance.

The daily loop

For one developer running one session at a time, three things are the whole system.

Register session start

Pins this session's file so concurrent sessions never read each other's counts. Automatic via hook in Claude Code and Copilot VS Code.

context-budget.sh register

Record every work-unit boundary

Measures, appends a ledger line, and returns OK, WARN or STOP as the exit code.

context-budget.sh record --label "…"

Roll over on WARN or STOP

The dying session writes its handoff and launcher, then starts the successor with a fixed bootstrap prompt.

skills/session-rollover/SKILL.md

WARN asks, STOP goes

  1. The dying session conducts its own rollover. Only it holds the conversation-only state that must reach disk.
  2. Write-ahead mode covers the ~30K grace window: settled points go to decision notes, open threads to the launcher, so the STOP rollover is cheap.
  3. Mid-discussion, the atomic step is the current exchange. Answer first, then roll over, carrying the live question into the launcher.

Relaunch modes

ROLLOVER_RELAUNCHWhat happens at rollover
offPrint the bootstrap prompt only; the supervisor refuses to run this item unattended
manualDefault. WARN asks the user, then runs the launcher
autoNo ask: the agent runs the launcher itself and the successor starts attached

A committed per-work-item context-budget.env may override the relaunch knobs; thresholds stay workspace-global.

Runtime fidelity

Each runtime gets one adapter that reads its session file. When parsing fails, the fallback is a bytes÷4 estimate, never “unsupported” — ±25% is fine given the WARN→STOP margin.

  • Claude Code exact
  • Codex exact
  • Copilot VS Code exact, can lag
  • Copilot CLI exact
  • Gemini CLI unverified

Copilot VS Code can under-report badly. Its token file flushes on its own cadence; one session read 34% while truly at 155%. Trust the Stop hook, and roll over at wave-scale boundaries regardless of the reported figure.
