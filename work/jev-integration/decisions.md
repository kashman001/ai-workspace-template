## 2026-09-27 — Fit decision: integrate Jev at the `rlm` leaf seam, gated on Jev access (PROPOSAL — node 03 approves or amends)
**Chose:** Integrate Jev at one seam, the `rlm` leaf classification (`skills/rlm/scripts/rlm_repl.py`: the `claude -p --model $RLM_SUB_MODEL` subprocess behind `llm_query`, lines 82/112/193), **gated on access**: the Jev path is taken only when `security find-generic-password -s jev-api-key -w` returns a key (macOS; other OSes per the documented keychain equivalent in `docs/service-access.md`). **A user without a key experiences nothing new: `rlm` runs the current `claude -p` path unchanged, and the absent key is not logged as an error.** Shape of the Jev path: batch-as-state (one request per 50-record batch, `state` = the record array, one Choice question per record referencing `` `records[i]` ``), an explicit `other` option appended to the root's category list, a confidence threshold below which the record falls back to the current path (threshold value fixed by the spec, tuned on real runs), model alias `jev-latest` by default with pinning to the versioned id once thresholds are tuned. Of session 6's four grill questions, **Q4 is the user's answer** (2026-09-25: option (a), optional path with the current runtime as default and fallback); **Q1, Q2 and Q5 are proposals** carried from session 6's recommendations for node 03 to confirm or amend: **Q1** axis of "serves better" = (c) determinism plus thresholdable `confidence`, latency second (not (a) output quality — parity on the one batch measured, not an eval; not (b) cost — negligible either way); **Q2** scope = narrow to `rlm` (the research-wave verdict seam noted as the next candidate; the other four rejected below); **Q5** the R0.4 lift = (a) orchestrator fact-finding now, widened to (b) dispatched agents by the spec if this note is approved.
**Because:** The API answers a caller-declared closed question with a typed answer and a probability (what-jev-is C28: questions reference nested `state` by path; integration-paths 6.2: many questions per request against one `state`), which is exactly the `rlm` leaf's shape — a root-declared category list applied to tens to hundreds of records per run, today regex-parsed from free text with no confidence and no `other`. The spike (`research/spike.md`) proved it end to end with the user's key: batch of five in 0.64s against 4.83s for `claude -p haiku` on the same records, identical labels, per-record `confidence` (1.0 / 1.0 / 0.98 / 0.89 / 0.99), `other` chosen once where the record fit nothing; O29 closed (sign-up works, key authenticates); the 255-option cap is server-enforced (400), so category lists are bounded by design. The API never abstains (integration-paths 5.1), so `other` is declared by the caller (5.2) and the confidence threshold is caller code (5.3), with the numbers being worked examples to tune, not defaults (5.4); Noul thresholds are its own (5.5) and pairing Choice with Noul (5.6) is out of scope for this seam; thresholds are version-sensitive, so tune on a pinned id (5.7). Cost is $42 per billion input tokens, output free (terms 1.1), with only a "we can serve it profitably" qualifier behind it (1.7) — budget on it, do not contract on it. Terms: published limits 250k tok/s and 1,200 req/min with 429 beyond (2.1); liability cap the greater of 12 months' fees or $50 (5.9); no SLA, only a "materially as described" warranty (7.3). Those terms are why the integration is gated rather than default: a seam that works without the key loses nothing when the vendor rate-limits, changes price, or is down.
**Rejected:** (a) always-on integration (Q4 b) — template downloaders and the other runtimes (Codex, Gemini, OpenCode, Copilot) have no key, the template ships credential-free, and ADR-0011 keeps nothing load-bearing on a model call; (b) the other five §5 seams first (Q2 wide) — research-wave per-claim verdict: the check's value is the re-fetch of the source, not the label (next candidate if `rlm` lands); triage category/state/severity: low volume and a human confirms anyway; doc-review severity/confidence: the finding text is open-ended, only the label is closed; decision-log tier/Promote?: a few per session, marginal; checkpoint learning routing: once per boundary, marginal; (c) no-go (Q4 c) — the spike shows the shape fits end to end at a fraction of a cent per batch, and gating removes the availability and terms risk that would otherwise justify it; (d) Q1 = (a) output quality — five records is not an eval, and a quality claim would need one; (e) Q5 = (c) reinstate R0.4 — the spec and its test need the orchestrator's key for the one live path, and the no-key test proves the other.
**Blast radius:** `skills/rlm/` (`scripts/rlm_repl.py` swap point, `SKILL.md` root instructions for `other` and the threshold), `docs/service-access.md` (Jev entry, key name, per-OS keychain read), `docs/runbooks/authentication.md` (how a person adds the key), `scripts/check-service-access.sh` (report key present/absent, never its value), a test that proves both paths without a live key (no key → current path byte-for-byte; key present → the Jev request shape against a stubbed endpoint). `research/` untouched.
