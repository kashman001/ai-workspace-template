# integration-paths / Q2 — MCP server, CLI, OpenAI-compatible endpoint, framework adapters, official SDK packages

Subject: Jev (TypeSafe, typesafe.ai). Cluster: `mcp-cli-adapters`. Date checked: 2026-09-23.
Method: raw HTML/JSON via `curl -sL` saved to scratchpad and grepped; docs pages read via
their `.md` renditions (`https://docs.typesafe.ai/<page>.md`, served by the docs host) and
`llms.txt` / `llms-full.txt`; registries via their JSON APIs. One WebSearch. No logins,
no API keys, no calls to `api.typesafe.ai/v1/*` (only its public `/openapi.json` and
Swagger UI page). The one POST issued was an unauthenticated MCP `initialize`/`tools/list`
handshake against `docs.typesafe.ai/mcp` (a docs-site server, not the model API).

Headline: TypeSafe itself ships **two SDKs (Python, JS/TS), an HTTP API, and an agent
skill** — no CLI, no Jev MCP server, no OpenAI-compatible endpoint. Framework adapters
exist but are published by the framework vendors (Vercel AI SDK, LangChain), not by
TypeSafe, and TypeSafe's docs do not mention them. A very large third-party ecosystem
(GitHub `typesafe jev` → 2,374 repos) supplies community MCP servers, CLIs and bridges.
